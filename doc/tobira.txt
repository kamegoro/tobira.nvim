1. INTRODUCTION                                             *tobira-introduction*

tobira.nvim watches your keystrokes and suggests the one command you are
missing, based on your actual usage patterns.

It runs silently in the background, tracks which commands you use, and when
it notices an inefficient pattern — like doing `dw` + `i` repeatedly when
`cw` exists — it waits until you are idle and quietly surfaces the better
path.

"Open the next door in your Vim journey."

2. SETUP                                                           *tobira-setup*

Install with lazy.nvim: >lua

  {
    "kamegoro/tobira.nvim",
    event = "VeryLazy",
    opts = {},
  }
<
Call `setup()` explicitly if not using lazy.nvim opts shorthand: >lua

  require("tobira").setup({
    lang = "en",
  })
<

3. COMMANDS                                                     *tobira-commands*

                                                                       *:Tobira*
:Tobira
  Show the next command suggestion immediately. Does not count toward the
  automatic suggestion cooldown.

  Unlike the ambient window described under AUTOMATIC SUGGESTIONS below,
  this manually-triggered window is "focused": it takes input focus, adds
  its own `q` / `<Esc>` / `<C-c>` keymaps to close it, shows an extra
  footer hint mentioning that binding, and closes itself if you switch to
  another window. It still auto-dismisses on its own after a few seconds,
  the same as the ambient window.

                                                                 *:TobiraStats*
:TobiraStats
  Show a usage statistics panel. Leads with "Try these next" — efficiency
  gaps, commands you use heavily whose neighbors you have not yet
  discovered — since that is the one section that actually changes what
  you do. A mastery bar and your top commands follow. Total keystrokes and
  how many commands you have discovered sit in a quiet line at the bottom.

  Inside the stats panel:
    `g`     Close stats and open the guide panel
    `p`     Close stats and open the progress panel
    `q`     Close the panel
    `<Esc>` Close the panel
    `<C-c>` Close the panel

                                                                 *:TobiraGuide*
:TobiraGuide
  Toggle a dynamic cheatsheet panel. Content adapts to your current mastery
  level — commands you have already mastered are hidden, and pinned
  commands are always shown at the top. A command that was mastered but
  whose recent use has fallen off well below its earlier pace reappears
  with a "forgotten" marker instead of staying hidden forever. Each category
  shows at most 3 unmastered commands, preferring ones you have never tried;
  if more are eligible, a "+N more" line reports how many were left out
  rather than growing the panel to fit everything.

  Mastery markers in the guide panel:
    `●`          Pinned — always shown at the top
    `☆`          Tried at least once
    (none, dim)  Never tried
    `⟳`          Forgotten — was practiced, has gone quiet

  The guide panel is passive and read-only, unlike |:TobiraProgress| and
  |:TobiraStats| — it has no keybindings of its own. Run |:TobiraGuide| again
  to close it, the same way you opened it.

                                                              *:TobiraProgress*
:TobiraProgress
  Open the skill tree panel. The header shows your current level and your
  overall `{n} / {total} mastered` ratio; each category heading shows its
  own `{done} / {total}`. Level-0 (never tried) commands render dimmed with
  no glyph. Move the cursor onto any command and a preview strip below the
  grid fills in with that command's usage sparkline, count, status, and how
  many uses remain to reach the next star.

  Mastery levels:
    `✗`     Suppressed (will not be suggested)
    (none)  Never used
    `☆`     Used at least once
    `★`     Used 100+ times
    `★★`    Used 1000+ times
    `★★★`   Used 5000+ times
    `⟳`     Forgotten — mastered, then recent use fell off well below its
            earlier pace (shown in the preview strip, not the grid glyph)
    `●`     Pinned — always shown, in both this panel and |:TobiraGuide|

  Inside the progress panel:
    `x`     Toggle suppress on the command under the cursor
    `p`     Toggle pin on the command under the cursor
    `g`     Close progress and open the guide panel
    `s`     Close progress and open the stats panel
    `q`     Close the panel
    `<Esc>` Close the panel
    `<C-c>` Close the panel

                                                                 *:TobiraReset*
:TobiraReset
  Reset all usage data. This clears the usage log stored at
  `~/.local/share/nvim/tobira/usage.json`.

                                                            *:checkhealth-tobira*
:checkhealth tobira
  Diagnose your install: Neovim version (and whether it is new enough for
  full `vim.on_key()` `typed`-argument accuracy), whether the data directory
  is writable, whether `usage.json` contains valid JSON, and whether the
  configured `lang` has a matching locale file.

4. CONFIGURATION                                                  *tobira-config*

Pass options to `setup()` or via the `opts` table in lazy.nvim.

Default configuration: >lua

  require("tobira").setup({
    lang               = "en",
    idle_delay         = 1500,
    idle_suggestions   = true,
    suggestion_cooldown = 300,
    max_shown          = 2,
    integrations       = true,
  })
<

                                                              *tobira-config-lang*
`lang` (string, default: `"en"`)
  Display language. Supported values: `"en"`, `"ja"`, `"zh"`, `"es"`, `"fr"`, `"de"`.

                                                       *tobira-config-idle_delay*
`idle_delay` (number, default: `1500`)
  Milliseconds of keyboard inactivity before an automatic suggestion may
  appear. Increase this value if suggestions feel intrusive.

                                                  *tobira-config-idle_suggestions*
`idle_suggestions` (boolean, default: `true`)
  Whether to show suggestions automatically after idle. Set to `false` to
  disable automatic suggestions and use only |:Tobira| for manual triggering.

                                                *tobira-config-suggestion_cooldown*
`suggestion_cooldown` (number, default: `300`)
  Minimum seconds between automatic suggestions. Prevents repeated
  interruptions within a short period.

  The terminal-mode suggestion (`<C-\><C-n>`, see below) is exempt from this
  cooldown: it only ever fires while you are actively stuck in terminal-job
  mode at that exact moment, so an unrelated suggestion earlier in the
  cooldown window never silently swallows it. It cannot spam you even
  without the cooldown — it fires at most once per uninterrupted `<Esc>`
  streak.

                                                       *tobira-config-max_shown*
`max_shown` (number, default: `2`)
  Maximum number of times the same command suggestion is shown per session.
  Resets to 0 on each Neovim startup.

                                                    *tobira-config-integrations*
`integrations` (boolean, default: `true`)
  Whether to boost a suggestion when a relevant helper plugin
  (surround.nvim/mini.surround, flash.nvim, leap.nvim, hop.nvim, and their
  mini.nvim/nvim-surround equivalents) is detected and its usage threshold is
  met. Set to `false` to disable this optional boost.
  This does NOT control whether tobira respects your own keymap overrides —
  that is always on, see |tobira-integrations|.

5. USAGE                                                           *tobira-usage*

AUTOMATIC SUGGESTIONS ~

tobira monitors your keystrokes using |vim.on_key()|. It detects patterns
such as:

  - Repeating `f` without using `;` to repeat the motion
  - Using `dw` followed immediately by `i` instead of `cw`
  - Pressing `x` multiple times instead of `{n}x`
  - Using `0` then `w w w` instead of `^`

Ex commands (anything typed after `:`, such as `:g`, `:norm`, or `:s`) are
tracked from the command line itself — not just normal-mode keystrokes — so
commands like `:g` and `:norm` can be suggested to users who have never used
them, the same way any other command is. A command line only counts once it
is actually submitted with <CR>; aborting with <Esc> never counts it.
tobira's own commands (`:Tobira`, `:TobiraStats`, `:TobiraGuide`,
`:TobiraProgress`, `:TobiraReset`) are excluded from this tracking, so
checking your stats or resetting your log never shows up as usage itself.

When a pattern is detected and you are idle for `idle_delay` milliseconds, a
suggestion appears in tobira's own floating window, near the top-right of the
screen. The window shows what you just did (when a specific pattern
triggered it), the command to try instead, and a short example. Its border
is colored by category (motion / edit / search / window / fold / mark /
macro / diff / ex / terminal) so a returning user can recognize the kind of
suggestion at a glance.
The window auto-dismisses on its own after a few seconds — roughly
scaled to how much text it is showing — and never steals focus or blocks
input. (Manually running |:Tobira| instead opens a distinct "focused"
variant of this window with its own close keymaps — see |:Tobira| above
for how it differs.)
The terminal-mode suggestion (`<C-\><C-n>`, see below) stays on
screen noticeably longer than the rest: it can only ever appear while you
are still mid-attempt to leave terminal-job mode, so it gets extra time to
actually be seen before it dismisses itself. For the same reason it is also
the only automatic suggestion exempt from |tobira-config-suggestion_cooldown|
— see that option's help for why.

A muted hint at the bottom of the window always shows how to silence that
suggestion via |:TobiraProgress|, even when the window did not steal focus.

ADOPTION DETECTION ~

After a suggestion is shown, tobira watches whether you actually use the
suggested command. It does this passively — no button press required.
If you use the command, it is marked as adopted and will not be suggested
again once mastered (100+ cumulative uses).

The very first time you adopt a given suggestion, tobira shows a brief
separate confirmation ("Nice — you used ...") so the loop of noticing a
habit and improving it is not left completely silent. This only fires once
per command, ever.

SUPPRESSION ~

If a suggestion is not relevant to you, open |:TobiraProgress| and press
`x` on the command to suppress it permanently. Suppressed commands are
marked with `✗` and will never be suggested again unless you unsuppress them.

DATA STORAGE ~

Usage data is stored locally at: >

  ~/.local/share/nvim/tobira/usage.json
<
No data is sent externally. The file is updated on |VimLeave|.

                                                          *tobira-integrations*
KEYMAP OVERRIDES AND PLUGIN INTEGRATIONS ~

tobira never intercepts or changes your keymaps — it only observes them
(see |tobira-introduction|). At startup, and again whenever Neovim finishes
starting up (`VimEnter`) or a plugin script finishes loading (`SourcePost`),
tobira reads your current `:map`/`:nmap`/`:nnoremap` state to find out which
of its own teachable commands you have personally remapped. A handful of
teachable commands are themselves insert-mode behavior — insert-mode
`<C-w>` (delete word), `<C-n>` (completion), `<C-t>` (indent), and
insert-mode `<C-o>`/`<C-d>` (run one normal command / dedent without
leaving insert) — tobira checks the matching `:imap`/`:inoremap` state for
these instead of the normal-mode one, so an unrelated normal-mode remap of
the same physical key (e.g. `nnoremap <C-n> :bnext<CR>`) never suppresses
them, and a genuine insert-mode remap always does.

If you have remapped a command tobira would otherwise suggest (for example
a plugin binding like `nmap s <Plug>(some-plugin-thing)`), tobira never
offers that command as a suggestion — introducing something you have already
deliberately bound to a different behavior would not teach you anything.
This applies to every proactive suggestion path, including the "Try these
next" efficiency-gap list in |:TobiraStats| — a command whose key you have
remapped never appears there either, even if its trigger's usage count would
otherwise qualify it.

tobira also tells apart a genuine remap from Neovim's own factory-default
mappings. Recent Neovim ships several teachable keys as built-in defaults
out of the box: `gx`, `&`, `]q`/`[q`/`]l`/`[l`, and (0.10+) even `Y` = `y$`
(see `:help Y-default`) instead of the Vi-compatible `yy`. None of these
count as a remap on a stock install — nothing was actually touched, so
they're suggested completely normally, exactly like any other
never-customized command.

Two narrow, curated exceptions cover a mapping that genuinely *was* set by
something (your own config, or a Neovim-shipped runtime plugin) but does
exactly what tobira already teaches. `Y`: if you personally add
`nnoremap Y y$` yourself (redundant with the modern default above, but a
real personal binding — e.g. on an older Neovim, or just out of habit), it
is recognized as functionally equivalent rather than a genuine override, so
it is still excluded from the proactive paths above like any other
override, but the reactive `y$` → `Y` suggestion (see DETECTED PATTERNS
below) still fires despite it. A `Y` remapped to anything other than `y$`
(e.g. restored to legacy linewise `yy`, or bound to something else
entirely) is treated as a genuine override and suppresses that suggestion
as usual.

The second exception is `%`: Neovim auto-loads `runtime/plugin/matchit.vim`
by default (`packadd matchit`), which does `nmap <silent> %
<Plug>(MatchitNormalForward)`. That target is a strict, compatible superset
of the built-in `%` for the basic bracket-jump behavior tobira teaches, so
it is recognized as functionally equivalent rather than a genuine personal
override. Like `Y`'s personal-remap case, it is still excluded from the
proactive paths above (|graph.find_best()| and the "Try these next"
efficiency-gap list in |:TobiraStats|) like any other override — unlike
`Y`, `%` has no reactive detected-pattern suggestion of its own, so the
practical effect of this exception is entirely in |:TobiraGuide| below: the
`%` row is shown with a "mapped to ..." note instead of being hidden
outright, on a stock install with matchit loaded. A `%` remapped to
anything other than matchit's target (e.g. a different jump plugin) is
treated as a genuine override and hides that row as usual.

|:TobiraGuide|'s auto-generated cheat-sheet still lists a remapped command if
the remap is functionally equivalent to what tobira documents (shown with a
"mapped to ..." note), but omits it entirely when the remap does something
unrelated (e.g. a `<Plug>` mapping into a different plugin). The Pinned
section at the top of the same panel is the one exception to "omit it
entirely": since you pinned that command on purpose, tobira never makes it
disappear silently. A functionally-equivalent remap still substitutes
wording exactly like the auto section; a different remap instead keeps the
row (so you can see your pin is still there) but replaces its description
with a "remapped to ... — no longer valid" note.

Because this check only runs at startup/`VimEnter`/`SourcePost`, a mapping
you create interactively afterwards (typing `:nnoremap` directly at the
command line) may cause one stale suggestion before tobira notices on its
next automatic refresh. This is expected and considered an acceptable
trade-off against re-checking keymaps on every keystroke.

Separately, when `integrations` (see |tobira-config-integrations|) is
enabled and tobira detects a supported helper plugin
(surround.nvim/mini.surround, flash.nvim, leap.nvim, or hop.nvim) alongside
enough usage of a related built-in command, it boosts a related suggestion
so it surfaces sooner. Plugin presence is detected by checking the
`runtimepath` for the plugin's Lua module — tobira never calls `require()`
on a plugin itself, so checking for it never forces a lazily-loaded plugin
to load.

6. DETECTED PATTERNS                                              *tobira-patterns*

Each pattern fires at most once per trigger sequence. After firing, the
suggestion is shown when you are next idle for `idle_delay` milliseconds.

MOTION ~

  `f{x}` → `f{x}` same line    Suggest `;`    — repeat the last f/t/F/T motion
  `l` × 5                       Suggest `w`    — jump forward by word
  `h` × 5                       Suggest `b`    — jump backward by word
  `w` × 5                       Suggest `W`    — jump forward by WORD
  `b` × 5                       Suggest `B`    — jump backward by WORD
  `e` × 5                       Suggest `ge`   — jump to end of previous word
  `j` × 5                       Suggest `{n}j` — use a count prefix instead
  `j` × 10                      Suggest `}`    — jump forward by paragraph
                                 (suggests `]c` instead while `&diff` is set — see DIFF below)
  `k` × 5                       Suggest `{n}k` — use a count prefix instead
  `k` × 10                      Suggest `{`    — jump backward by paragraph
                                 (suggests `[c` instead while `&diff` is set — see DIFF below)
  `k` (once) → `o`              Suggest `O`    — open new line above directly
  `0` → `w`                     Suggest `^`    — go to first non-blank
  `0` → `i`                     Suggest `gI`   — insert at true column 1
  `^` → `i`                     Suggest `I`    — insert at first non-blank
  `$` → `a`                     Suggest `A`    — append at end of line
  `n` × 4                       Suggest `cgn`  — change next search match
  `G`/`gg`/`n`/`N`/`<C-d/u/f/b>` → `j`/`k`/`<C-e>`/`<C-y>` × 5 (within 15s)
                               Suggest `<C-o>` — jump back with the jumplist
  edit → move → edit elsewhere → `j`/`k` × 5 back (within 15s)
                               Suggest `g;`   — jump back with the changelist
  `G` → `gg` (or `gg` → `G`), back to back
                               Suggest `''`   — jump back to your previous spot
  `<C-e>` / `<C-y>` × 5 (any mix)
                               Suggest `zz`   — center the cursor line on screen

EDIT ~

  `c$`                          Suggest `C`     — change to end of line
  `d$`                          Suggest `D`     — delete to end of line
  `y$`                          Suggest `Y`     — yank to end of line
                                 (still fires even with Neovim's own default
                                 `nnoremap Y y$` in place — see the narrow
                                 exception under KEYMAP OVERRIDES above)
  `dw` → `i`                    Suggest `cw`    — change word in one motion
  `yy` → `p`                    Suggest `yyp`   — duplicate the current line
  `dd` → `p`                    Suggest `ddp`   — swap current line with next
  `dd` → `i` / `a` / `o`       Suggest `cc`    — change whole line
  `dd` × 3                      Suggest `{n}dd` — delete N lines at once
  `ci"` × 3 (direct, not visual; nav ok between) Suggest `ya"` — yank around double quotes
  `ci'` × 3 (direct, not visual; nav ok between) Suggest `ya'` — yank around single quotes
  `D` → `i` / `a` / `o`        Suggest `C`     — change to end of line
  `x` (once) → `i` / `a` / `o` Suggest `s`     — substitute char (delete + insert)
  `x` × 3                       Suggest `{n}x`  — delete N chars at once
  `p` × 3                       Suggest `{n}p`  — paste N times
  `P` × 3                       Suggest `{n}P`  — paste above N times
  `~` × 3                       Suggest `{n}~`  — toggle case of N chars
  `~` × 6 (consecutive chars)   Suggest `g~iw`  — toggle case of the inner word
                                 (supersedes `{n}~` once the streak plausibly
                                 spans a whole word)
  `~` × 12 (consecutive chars)  Suggest `g~$`   — toggle case to end of line
  `.` × 3                       Suggest `{n}.`  — dot-repeat with a count
  `J` × 3                       Suggest `{n}J`  — join N lines at once
  `u` × 3                       Suggest `<C-r>` — redo instead of repeating undo
  `r{x}` × 3 (h/l between ok)  Suggest `R`     — enter Replace mode directly
  `>>` × 3                      Suggest `{n}>>` — indent N lines at once
  `<<` × 3                      Suggest `{n}<<` — dedent N lines at once
  `v` `i/a` `{obj}` `c/d/y`    Suggest direct operator (e.g. `ciw`, `di"`, `ya(`)
  `v` → `<Esc>` × 3            Suggest `gv`    — reselect the last visual selection
  `p` / `P` → rightward × 3    Suggest `gp` / `gP` — paste, leave cursor after it
  `<C-a>` → `j` × 3             Suggest `g<C-a>` — visual-block sequential increment
  `gq` → jump back              Suggest `gw`    — format without moving the cursor
  Identical `:s/pat/repl/` on a 2nd line
                                Suggest `&`     — repeat the last substitute here
  Identical `:s/pat/repl/` on a 3rd line
                                Suggest `g&`    — repeat it across the whole file
  Same single-line edit (e.g. `A;<Esc>`) on 3 consecutive lines
                                Suggest `<C-v>` — block-visual edit them all at once
                                 (cursor must move by exactly one line, `j`,
                                 between repeats; excludes operator+motion
                                 shapes like `cwFoo<Esc>`, which stay in the
                                 MACRO pattern below)

WINDOW ~

  `<C-w>q` / `<C-w>c` × 2       Suggest `<C-w>o` — close all other windows
  `<C-w>+` / `<C-w>-` / `<C-w><` / `<C-w>>` × 2 (any mix)
                                Suggest `<C-w>=` — equalize all window sizes

MARK ~

  Cursor returns to the same line × 3, with a real edit elsewhere
  between each return            Suggest `ma`    — set a named mark here
                                 (does not fire from a tight, edit-free
                                 scroll-back streak — that is `<C-o>`'s
                                 domain above)

MACRO ~

  Same edit sequence × 3        Suggest `qq...q` / `@q` — record and replay a macro
                                 (navigation allowed between repeats; not suggested
                                 while already recording, or if the sequence itself
                                 contains `q` or `@`)

  Same Ex command line retyped verbatim, 2nd submission
                                Suggest `q:`    — open the command-line
                                 window and recall it from history instead
                                 of retyping it (skips `:s///`, already
                                 covered above under EDIT, and `:e`/`:b`/
                                 `:tabnew`, covered below under EX; also
                                 skips a bare command with no argument,
                                 e.g. `:w`, `:q`)

DIFF ~

  `j` × 10 (while `&diff`)      Suggest `]c`    — jump to the next diff hunk
  `k` × 10 (while `&diff`)      Suggest `[c`    — jump to the previous diff hunk
  Insert-mode edit right after `]c`
                                Suggest `do`    — diff obtain: pull the hunk in
  Insert-mode edit right after `[c`
                                Suggest `dp`    — diff put: push the hunk out

INSERT MODE ~

  `<BS>` × 5                    Suggest `<C-w>` — delete the whole word at once
  `<Left>` × 5                  Suggest `b`     — leave insert, jump back a word
  `<Right>` × 5                 Suggest `w`     — leave insert, jump forward a word
  Empty insert → `<Esc>`, twice Suggest `A`     — stop bouncing in and out, append directly
  Same 6+ char word, twice      Suggest `<C-n>` — complete the word instead of retyping it
  `<Esc>` → 1 motion → `i`      Suggest insert-mode `<C-o>` — run one command, stay in insert

TERMINAL MODE ~

  `<Esc>` × 2, no effect        Suggest `<C-\><C-n>` — exit terminal mode

EX ~

  `:e A` → `:e B` → `:e A`      Suggest `<C-^>` — jump straight to the alternate file
  (or the equivalent with `:b`)
  `:tabnew {distinct file}` × 3, one window per tab
                               Suggest `<C-^>` — switch buffers instead of a
                                 tab per file (a window split inside any of
                                 the tabs resets the count — that is a
                                 legitimate multi-window layout, not
                                 one-tab-per-file browsing. Re-opening a file
                                 you already have open in another tab also
                                 resets the count, rather than counting
                                 toward it — Vim reuses the existing buffer,
                                 so that is not "another file" either)

7. TROUBLESHOOTING                                       *tobira-troubleshooting*

START HERE: :checkhealth tobira ~

Before anything else, run |:checkhealth-tobira|. It checks four things:

  1. Neovim version — errors if below 0.9 (the minimum tobira supports),
     warns if below 0.10 (`vim.on_key()`'s `typed` argument is not
     available there, so tracking accuracy is reduced but tobira still
     works).
  2. Whether tobira's data directory is writable, or can be created.
  3. Whether `usage.json` contains valid JSON.
  4. Whether the configured |tobira-config-lang| has a matching locale
     file.

Most of the symptoms below trace back to one of these four checks
failing.

NO SUGGESTIONS EVER APPEAR ~

Check these, roughly in order of likelihood:

  1. `:checkhealth tobira` reports the data directory is not writable.
     If usage can never be saved, no command's count ever crosses a
     threshold, so nothing looks "used enough" to suggest.
  2. `idle_suggestions = false` in your config. This only disables the
     ambient idle-timer suggestion — the one picked with no specific
     trigger. Suggestions that react to a detected pattern (repeating
     `f`, `dw` then `i`, and so on) are not gated by this option and
     still fire after |tobira-config-idle_delay|. If you see neither
     kind, keep checking the causes below.
  3. `suggestion_cooldown` is set very high. Automatic suggestions —
     ambient and pattern-triggered alike — wait at least this many
     seconds after the previous one. Run |:Tobira|, which always
     bypasses the cooldown, to check whether tobira has anything to
     say right now.
  4. Every command tobira could suggest is already mastered (100+
     uses), suppressed (`x` in |:TobiraProgress|), already shown
     `max_shown` times this session, or bound to a key you have
     personally remapped — see |tobira-integrations|, which never
     offers a suggestion for a command you have deliberately bound to
     something else. |:TobiraProgress| shows the state of every
     command; |:TobiraStats|'s "Try these next" section is the
     fastest way to see what is left.
  5. `:Tobira` printing "no new suggestions right now" is the expected
     message once none of the above apply — not an error.

USAGE.JSON LOOKS CORRUPTED, OR MASTERY SEEMS STUCK/WRONG ~

Run |:checkhealth-tobira| first — it validates `usage.json` as JSON
and reports its exact path. If the file is not valid JSON, tobira does
not error: it silently treats usage as empty until the file is fixed,
which looks like every command has reverted to "never used".

The file lives at: >

  ~/.local/share/nvim/tobira/usage.json
<
To start over deliberately, run |:TobiraReset|. It erases the file
completely — counts, per-session history, suppressed/pinned state, and
mastery all go back to zero, with no partial undo. It does NOT touch
your `setup()` options (`idle_delay`, `suggestion_cooldown`, and so
on) — those live in your config, not in usage data.

SUGGESTIONS TOO OFTEN / NOT OFTEN ENOUGH ~

Three independent knobs, all documented in |tobira-config|:

  `idle_delay` (default 1500ms) — how long you must pause before any
  suggestion, ambient or reactive, can appear. Raise it if suggestions
  feel too eager.

  `suggestion_cooldown` (default 300s) — minimum gap between automatic
  suggestions. Raise it to see tobira less often overall; |:Tobira|
  always ignores it.

  `max_shown` (default 2) — how many times the same command is
  suggested per session before tobira moves on to something else.
  Resets on every Neovim startup.

If a specific suggestion feels boosted for the wrong reason, check
`integrations` (default `true`, see |tobira-config-integrations|) — it
promotes a suggestion when a supported plugin (surround.nvim,
flash.nvim, leap.nvim, hop.nvim, or their mini.nvim equivalents) is
detected. Setting it to `false` disables only that boost, not tobira's
other suggestions.

STILL STUCK ~

Open an issue at https://github.com/kamegoro/tobira.nvim/issues with
the output of |:checkhealth-tobira| attached.
